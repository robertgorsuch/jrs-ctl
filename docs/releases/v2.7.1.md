# jrsctl 2.7.1

jrsctl 2.7.1 is a patch release with four fixes from a code review of the 2.7.0 features. Three of them are in `repository load` and the doctor gates of the commands that change things. One of those, a crashed run being overlooked by the doctor gate, also affected `upgrade`, which has had it since the gate was written. Nothing else changes: JasperReports Server 7.1 to 10.x on Apache Tomcat, on Windows or Linux (64-bit), with a bundled Java 21 runtime.

Download the archive for your system below, check it against its `.sha256` and its signature (`SECURITY.md`), and unpack it. It includes its own Java; nothing needs to be installed on the server.

## Read this before upgrading from 2.7.0

| What changed | What to do |
|---|---|
| **The doctor step of `upgrade`, `passwords migrate` and `repository load` now stops on any other pending run or a lock held by another run.** Inside a run, the doctor leaves out only that run's own pending entry and lock; those two items now read PASS in the run's log instead of FAIL with "(this run itself; not a problem with the host)". | If one of these commands now stops at the doctor step naming a run, resume or roll that run back first (`jrsctl runs recover <id> --resume` or `--rollback`), as the message says. |

No configuration key, command or flag changed.

## Fixed

- **`repository load` could not run on MySQL** (#298). `render-config` compared the rendered `metadata.jdbc.url` with the configured `database.url` including the query string. The vendor's MySQL template adds `?useUnicode=true&characterEncoding=UTF-8&...`, so the step reported "names the server of ..." and ended the run with exit 3 unless `config.yaml` carried exactly the same parameters. The two URLs are now compared by database type, host, port and database name; a different host or port is still refused.
- **A crashed run could be overlooked by the doctor gate of `passwords migrate` and `upgrade`** (#299). Inside a run, the doctor's `runs` item lists the run itself as pending. The gate ignored the whole item whenever its text named the current run, so with a crashed run beside it (`2 pending run(s): r-A, r-B`) the gate passed and the run went ahead on top of a half-finished one. The doctor is now told which run it runs inside and leaves out exactly that one; any other pending run, and a lock held by another run, stop the gate.
- **`repository load` did not check for other pending runs or the run lock** (#301). Its doctor step now requires the `runs` and `lock` items too, so a schema is not created beside a half-finished run.
- **`export --full-server` could not run from a tools-only configuration** (#300). Strategy selection treated the tools-only buildomatic as an installation and chose `js-export`, which planning then refused. A tools-only configuration now uses the REST `everything` export, as from any machine without the installation (ADR-0051).

## Known limitations

- **`repository load` and `passwords migrate` have never run against a live server.** Every step, these fixes included, is tested against fake `js-ant` and `js-import` scripts and a fake JDBC catalogue. Try `repository load` on a copy of a repository first, and keep the DBA's `DROP DATABASE` for the schema it names ready.
- **`repository load` supports PostgreSQL and MySQL.** Oracle, SQL Server and DB2 are refused while planning with exit 6.
- **`passwords migrate` needs the deployed webapp on its host**, and jrsctl does not run inside a container (ADR-0043).
- **The REST `everything` export may lack calendars.** `export --full-server` on the server host is `js-export --everything` and carries them.
- **`import verify` compares by id, not by content.**
- **jrsctl does not move a Windows service or systemd unit to a new Tomcat.**
- **Paths verified only against fake vendor scripts:** as listed in the 2.7.0 notes.
- **Buildomatic on a network share** (#31), **the adapter against live servers other than 10.0.0 PRO** (#35), **Windows containers are not detected**, **`logs/jrsctl.log` is not rotated**, **the pager** in unusual consoles: as in 2.7.0.
