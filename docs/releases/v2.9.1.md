# jrsctl 2.9.1

jrsctl 2.9.1 is a patch release with one security fix: the output filter that masks passwords missed some of them in JSON output and in `password.escapeXML=` properties (#369). It was found in a field run of `customizations scan --json`, where the diffs of installer-written files such as `META-INF/context.xml` showed the site's repository-database password in clear text. Nothing else changes: JasperReports Server 7.1 to 10.x on Apache Tomcat, on Windows or Linux (64-bit), with a bundled Java 21 runtime.

Download the archive for your system below, check it against its `.sha256` and its signature (`SECURITY.md`), and unpack it. It includes its own Java; nothing needs to be installed on the server.

## Read this before upgrading from 2.9.0

| What changed | What to do |
|---|---|
| **Output written by 2.9.0 or earlier may hold passwords** (#369): `--json` output that quotes a file with `password="…"` attributes (the installer-file diffs of `customizations scan`), and any output that shows a `….password.escapeXML=` line from `js.jdbc.properties`. Such JSON may also not parse. | Delete or redact saved `customizations scan` reports, and support bundles or logs you have passed on, made with an earlier version. Rotate any database password they show. |

No configuration key, command or flag changed.

## Fixed

- **Passwords in JSON-escaped attributes were left in clear text** (#369). In `--json` output, an XML attribute such as `password="x"` inside a quoted file reads `password=\"x\"`. The filter masked only the backslash, so the value stayed readable and the unescaped quote left behind made the JSON invalid. The value is now masked as `\"[redacted]\"`, and the JSON stays valid.
- **`password.escapeXML=` and other dotted password keys were not masked** (#369), in text output as in JSON. A key whose name is a password word followed by a dotted suffix is now masked.
- **A masked value could swallow the lines after it in JSON output** (#369). A bare value ran across an escaped line break (`\n`) and hid the following lines of a diff; it now ends there.

The fix is in the shared redaction filter, so every `--json` output, the log and the support bundle get it, not only `customizations scan`.

## Known limitations

- **Regressions in 2.9.1, fixed in 2.9.2** (found by a review after the release): in plain-text output (terminal, log, support bundle) a bare `password=` or keytool `-storepass`/`-keypass` value that holds a backslash followed by `"`, `/`, `b`, `f`, `n`, `r`, `t` or `u` is masked only up to the backslash, where 2.9.0 masked it whole; `password.strategy=` and `password.algorithm=` settings are shown as `[redacted]` in `passwords status`, `passwords migrate` and the upgrade checks; and in JSON output a `password=\"` left open on one line of a quoted file can leave the next line's value in clear text. Use 2.9.2.
- **As in 2.9.0:** the upgrade fixes of 2.9.0 are tested against fake vendor scripts only; `runs abandon` does not check that the server is right; vendor-strategy `export`, `import` and `passwords` use `vendor.javaHome` only; and the 2.8.0 limitations listed in the 2.9.0 notes still apply.
