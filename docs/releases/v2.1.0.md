# jrsctl 2.1.0

This release acts on the third field test, a JasperReports Server support engineer working through v2.0.0 end to end. Every finding was checked against the code first, and these fixes cover the ones that blocked the test or made the tool hard to use: where jrsctl keeps its data and how much room it needs, which installation `init` picks, how often a restore stops the server, and how the guided menu asks its questions. It also completes the web console removal that 2.0.0 announced.

Download the archive for your system below, check it against its `.sha256`, and unpack it. It includes its own Java; nothing needs to be installed on the server.

## Read this before upgrading from 2.0.x

| What changed | What to do |
|---|---|
| **A leftover 1.x `console:` block is refused** (#154, ADR-0038). 2.0 loaded a `config.yaml` that still had it, with a warning that 2.1 would refuse it. Every command now stops with exit **2**, naming the block and the fix. The same applies to `console.*` lines in `jrsctl.properties`. | Run `jrsctl config unset console` once. It is the one command that still reads such a file; it removes the block and keeps `config.yaml.bak`. |
| **A buildomatic import stops the server once, not twice** (ADR-0040). The rollback copy taken before the import now runs with the server up, so the outage covers `js-import` only. | Nothing. A run interrupted under 2.0.x still recovers with its original steps. |
| **`--help`, `--version` and the documentation say "Jaspersoft"** instead of "Actian Jaspersoft". The guided menu names no company. | Update any script that matches the old banner text. |
| **`export --legacy-key` is the documented name** for encrypting with `deprecatedImportExportEncSecret`, the key Jaspersoft's import screen calls the Legacy key. | Nothing; `--portable` still works. |
| **The guided menu's back-up entry has one "Everything" option.** Its question, whether to include scheduled report jobs and calendars, decides between buildomatic's `js-export` and the server's REST export. | Nothing. |

## New

- **`jrsctl home show|set|reset`** (ADR-0041). `home show` says where jrsctl keeps its state, backups and logs, what chose that location, how much room its volume has and what uses it. `home set <dir>` moves the home to a bigger volume for every operator and scheduled task on the machine, by writing a redirect in the old home; `home reset` undoes it. Nothing is copied, and `set` refuses while the old home still holds installed hotfixes, registered customizations or runs pending recovery. The guided menu's settings entry offers all three.
- **`init` lists every installation it finds**. It ranks a running one first and then the highest version (10 before 9, compared as numbers, not as text), and asks which to use. When it can't see a running server because it isn't elevated, it says so.
- **`import --no-snapshot`** skips the pre-import rollback copy for operators who have their own backup. The override is audited, and the plan warns that a failed import can then only delete what it added, not put back what it overwrote. When `--strategy vendor` is forced but REST would have worked, the plan says the REST route needs no outage.
- **Guided menu**:
  - The settings are listed first, numbered. You pick one by number or name (Tab completes names), and its current value is already on the line to edit. `-` removes a setting, and a password is asked for hidden.
  - Every prompt supports arrow keys and cursor movement on a real terminal.
  - When the archive has a `.jrsctl.json`, the restore entry reads the key alias from it instead of asking.
  - The menu says "buildomatic", and `--strategy buildomatic` is accepted as another name for `vendor`.

## Fixed

- **Running out of space** now says where and what to do. The hotfix preflight, the unpacking and conversion of official packages, the snapshot store and the upgrade backup all name the jrsctl home and point to `runs prune` or `home set`, in GB. A full disk is no longer reported as a bad download or bundle. `doctor`'s `disk` item says which volume is short and gives the advice that fits it.
- **Converted official hotfix packages** under `runs/` are now pruned by age.
- **`init` chose JRS 9 over a running JRS 10** because it took the first installation found and sorted version folders as text.
- **The guided menu's "Everything" backup could leave out events**: a full-server `js-export` doesn't include them, so the events question is now asked for every backup.
- **Setting values in the menu** now pass through the redaction filter, as `config show`'s do. An unreadable settings file can be replaced from the menu.

## Documentation

- ADR-0040 (one outage per import, amending ADR-0021 §4) and ADR-0041 (moving the home with a redirect file).
- The operator guide and the spec (§5.1, §9, §12.4) are updated to match, with a spec changelog entry for each.
- The wiki has a Testing Locally page.

## Known limitations

- **Arrow-key editing** at every prompt needs a real terminal; piped input and very old consoles get plain line input.
- **Moving the home copies nothing**: the old home keeps its snapshots at their recorded paths until you delete it.
- **Still open from the third field test**: a pager for the embedded documentation, filters and friendlier ids for `runs list`, building from a source archive or as root, the hotfix staging that runs during the outage, and checking the sidecar's recorded checksum on import.
