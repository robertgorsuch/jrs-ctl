# jrsctl 1.8.0

This release acts on the second field test of 1.6.0 (all 33 findings, each checked against the code) and on the rest of the vendor documentation review. Before it was tagged, the riskiest new code was also run against a real JasperReports Server 10.0.0 PRO, which found a rollback bug that is fixed here (below). The theme is making the difficult jobs (upgrade, export and import, official hotfixes) do what an administrator expects and say what they did.

Download the archive for your system below, check it against its `.sha256`, and unpack it. It includes its own Java; nothing needs to be installed on the server.

## Read this before upgrading from 1.7.0

| What changed | What to do |
|---|---|
| **A failed `import` now deletes what it created** (#100, #139; ADR-0031, ADR-0036). The rollback deletes additions under the folders it snapshotted, and the folders that did not exist before the import (with their content), then re-imports the snapshot. Before, a failed import left everything it had created, and for a folder that did not exist yet the run still said "rolled back". The plan summary says what will be deleted. | Nothing to change. Anything someone else creates in those folders between the start of the import and its failure is deleted with them (the plan says so). If a deletion fails the run exits **4** and names the folders left. Users, roles, settings and events an archive carries are not tracked, and an organisation the import creates has to be removed with `DELETE /rest_v2/organizations/<id>`. |
| **`import` refuses a catalog exported from 10.1 or later into a server below 10.1** (exit **2**, nothing written; #107). The vendor says such resources cannot be imported there. | Import into a 10.1 server, or pass `--force-version` to try anyway (audited). |
| **Imports above 2 GB do not use REST** (#115). The vendor does not recommend it and the server fails such an upload after the long transfer. | With the vendor tools on this machine the import uses them; without, planning exits **2** naming `--strategy rest`, which uploads it anyway. |
| **Themes are skipped when the archive comes from another major version** (#115). An old theme may not fit the new one. | The plan says so. Pass `--themes` to import them. |
| **`config set` and `init` refuse a path setting whose directory does not exist** (exit **1**), and a leading `~` is expanded everywhere a path is read. | Create the directory first. |
| **The `newdb` upgrade no longer asks for a database backup confirmation.** `upgrade rollback --restore-database` rebuilds the old database from the export taken at the stop (ADR-0029), so the question stays for `samedb`, where the script migrates in place. | Nothing; `samedb` still asks. |
| **The upgrade refuses earlier for vendor preconditions**: a missing licence file for a commercial 10.0+ target, a missing JDBC driver jar for Oracle, SQL Server and DB2 (#108). | Place the licence in the user home of the account that runs the script and the driver jar in the target's `buildomatic/conf_source/db/<db>/jdbc/`. |
| **Starting the service starts the bundled PostgreSQL first** (`jasperreportsPostgreSQL`, then Tomcat) and clears a stale `catalina.pid`; systemd socket units are driven with their service (#113). | Nothing on a normal install. |

## New

- **Official Jaspersoft hotfix packages apply on a confirmed checksum** (ADR-0027). From a terminal `hotfix apply <package.zip>` prints the package's SHA-256 and asks whether it matches the support portal; no flag, key or manifest is involved. Unattended runs keep `--allow-unsigned`. The guided menu applies them too. `jrsctl hotfix record <package.zip>` enters a package applied by hand into the ledger so `hotfix list` and `upgrade` know it (#99, ADR-0030).
- **Upgrade:**
  - `--export <file>` adopts an export taken earlier or on another server, decrypted by `--key-alias` (ADR-0028).
  - `--test` rehearses with the vendor's own validation and changes nothing.
  - `rollback --restore-database` rebuilds a `newdb` upgrade's database from the export.
  - `--include-events` imports the access, audit and monitoring events `js-upgrade-newdb` leaves behind (#106).
  - `--migrate-passwords` for `samedb` to 10.1+, and a JNDI check for 9.0 targets.
  - The backup space is budgeted before anything changes and the plan names where backups go.
  - `--tomcat-dir` tells you how to re-register a service and warns about a missing `--add-opens` (#109).
- **Export and import:**
  - `--key-alias` and `--portable` choose the key an archive is encrypted with (`--portable` uses the alias every keystore since 7.5 holds, so another server can import it).
  - `--organization` and `--merge-organization` export and import one organisation.
  - `export` refuses a `--uri` the server does not have and shows the server's error descriptor.
  - `--force-version` and `--themes` (above).
- **`doctor`** runs without the admin password and never prompts for the passphrase; problems print first with a one-line summary. New items: `telemetry`, `audit`, `database-service`, `pid-file` and `cluster`, a warning for a keystore readable beyond its owner, and for basic authentication with non-ASCII credentials. The elevation check on Windows takes 80 ms instead of 3 to 4 seconds on a domain-joined machine.
- **Guided menu** lists the embedded documentation, changes several settings in one visit, labels the exports by mechanism (REST or vendor tool) and asks the import and upgrade options that were unreachable before. Tables and help wrap at the terminal width.
- **`customizations scan --tomcat`** lists the Tomcat-side files an upgrade does not carry over (`bin/setenv.*`, `server.xml`, context fragments, added `lib` jars); the 8.2 Hibernate path is recognised; a file under `scripts/` earns a warning, because since 8.0 that tree is a rebuilt overlay, not a set of files (#117).
- **The support bundle** carries the vendor's logs (buildomatic script log, `jasperserver.log`, Tomcat log, `installation.log`), tail-capped and redacted (#111). The server session is ended after every run (#114).
- **Windows** service stop and start are about 40% faster for the `catalina`, `ctlscript` and `manual` service kinds (the Windows service kind was not affected).

## Fixed

- A failed import of new content left everything it created and reported a rollback (above; found by the live check).
- The keystore was looked up in buildomatic's copy before the running server's own (#105).
- `hotfix list` showed nothing for a hotfix applied before jrsctl existed; the CLI printed the wrong message for an official package and the menu could not apply one at all.
- An upgrade could fill the jrsctl home's volume with its backups and full export and give no warning.

## Verified against a real server

Run against a JasperReports Server 10.0.0 PRO before this release (REST only, one scratch folder, a full export taken first and compared after; the repository ended identical):

- import rollback in three shapes (folder exists, parent exists and folder absent, nothing exists) plus a good import that deletes nothing;
- a `--portable` export and import round trip (the server accepts the `keyAlias` fields);
- organisation export, import and import into a second organisation with `--merge-organization`;
- `doctor`, with and without the admin password.

**Not verified live**, because they need a disposable installation or elevation this machine does not have: `upgrade --export`, `--test`, `rollback --restore-database` and the key alias reaching the vendor import; an official hotfix package from support (checked against the documented layout only); the vendor-tool strategy's rollback of new content; and the Linux service paths (systemd socket units), which CI exercises with fakes. Treat those as new.

## Known limitations

- **From the field test, open:** the guided menu has no path completion or cursor movement (#102, needs a line-editing library and an ADR); backups cannot yet be moved without moving the whole jrsctl home (#101, `--home` or `JRSCTL_HOME` moves it); no full-screen terminal UI (#75).
- **The operator guide has not had a support engineering review** (#36), the `needs-jrs` live suite has no JasperReports Server image (#35), buildomatic on a real UNC share or network mount is unverified (#31), and JBoss, WildFly and container installs are undecided (#118).
- **Live exports (#67):** unchanged from 1.6.0; use `--stop-service` for a point-in-time export.
- **Git Bash on Windows** rewrites repository paths such as `/public/Samples` into file paths; use `cmd` or PowerShell, or set `MSYS_NO_PATHCONV=1`.
