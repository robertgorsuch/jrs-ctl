# jrsctl 2.0.1

This release fixes what the first real use of 2.0.0 turned up. An official cumulative hotfix was applied to a JasperReports Server 10.0.0 PRO, and its support bundle was reviewed file by file; every defect found there is fixed here (#157 to #161). It also finishes the 1.x-to-2.0 path the web console removal started.

It is numbered as a patch at the maintainer's choice. Three changes can alter what an operator sees, so read the table below before upgrading.

Download the archive for your system below, check it against its `.sha256`, and unpack it. It includes its own Java; nothing needs to be installed on the server.

## Read this before upgrading from 2.0.0

| What changed | What to do |
|---|---|
| **`hotfix apply` and `hotfix rollback` refuse to change files whose owner they cannot put back** (#157, ADR-0039). A 2.0.0 hotfix run from a non-elevated Windows prompt left 178 replaced files, `WEB-INF\lib` jars included, owned by the operator's account instead of `BUILTIN\Administrators`, and still reported success. Preflight now checks, without changing anything, whether this account may give each owner back, and stops with exit **2** when it may not. | Run hotfixes from an elevated prompt (Windows), or as root or the owning account (Linux). Files a 2.0.0 run already left owned by your account pass the check as they are; give them back with `icacls <file> /setowner "BUILTIN\Administrators"` from an elevated prompt (the paths are in that run's `logs/jrsctl.log`). |
| **The support bundle's layout changed** (#160, #161). `plan.json` is gone: `run.json` already carries the identical plan, now with its `{runId}` placeholders filled in. `logs/jrsctl.log` holds that run's own lines instead of the last 2,000 lines of the whole log, and `logs/tail-jrsctl.log` holds the last 200 for context. | Nothing to do. Anyone who reads bundles should look for the plan in `run.json`. |
| **`doctor` warns about a password that equals its username or is a vendor installer default** (#158). Redaction cannot hide such a password, because it masks the word wherever it appears. A bundle from a server using the bundled PostgreSQL's default password had 2,883 redactions in `installation.log` alone. | Change the password on the server or database, then store the new one with `jrsctl config set <key>`. The warning names the setting, never the value. |

## Fixed

- **An official hotfix confirmed by its checksum was reported and audited as `--allow-unsigned`** (#159). The plan, the verify step and the audit row (`hotfix.checksum-confirmed`) now say the operator confirmed the checksum. `--allow-unsigned` is reported only when it was given, and `runs recover` keeps the distinction. Every audit row now names the operating-system account that ran jrsctl; commands used to write `operator`.
- **`jrsctl config unset console` removes the 1.x `console:` block** (ADR-0038). The 2.0.0 warning told operators to remove it, but `config unset console.*` was refused. The warning now names the command. jrsctl 2.1 will refuse the block (#154).
- **The support bundle carried another run's buildomatic log** (#161). It is now the newest one written while that run executed, and a run that ran no vendor script gets none.
- **Without `--out`, `runs support-bundle` could write into the unpacked distribution** (#161). A bundle made from inside the distribution now goes to the jrsctl home, and the full path is printed.
- **Tab at a path prompt printed a JLine warning** ("does not support the CompletingParsedLine interface"). Completion works the same, without the warning.

## New

- **The JSON log records every run** (#160): one line per invocation, run start, step transition and run end, and every line written during a run carries its `runId`.

## Documentation

- ADR-0039 (refuse a swap that would lose file owners) and an ADR-0027 amendment (how an unsigned package was accepted).
- The operator guide, spec §12.4 (support bundle entries), the security notes and the spec changelog are updated to match.
- The wiki is updated for 2.0 and has a new **Testing Locally** page.
