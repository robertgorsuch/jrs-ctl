# jrsctl 2.8.0

jrsctl 2.8.0 adds the checks and records a move from 8.2 to 10.x needs, from the NGRA upgrade guide reviewed against the tool (#304 to #309): report job states kept across the move, each site file classified against the target version, a readiness report for Jakarta EE and Java 17, an `import verify` that compares content, and a CI gate on `doctor`, `smoke` and `import verify`. Nothing else changes: JasperReports Server 7.1 to 10.x on Apache Tomcat, on Windows or Linux (64-bit), with a bundled Java 21 runtime.

Download the archive for your system below, check it against its `.sha256` and its signature (`SECURITY.md`), and unpack it. It includes its own Java; nothing needs to be installed on the server.

## Read this before upgrading from 2.7.2

| What changed | What to do |
|---|---|
| **`export` also lists the server's report jobs** (`GET /rest_v2/jobs`) in its sidecar step and records each job's state in the sidecar (#309, ADR-0059). A listing the server refuses never fails the export; the sidecar then says why no states were recorded. | Nothing. |
| **The sidecar is version 2** (`sidecarVersion: 2`, with a `jobs` block). jrsctl 2.7.2 and earlier read it and ignore the new fields. | Nothing. |

No configuration key changed. Every new flag is optional, and without one the existing commands behave as in 2.7.2.

## New

- **Report jobs across a move** (#304, ADR-0056). `jobs record` writes every report job's id, label, report, owner and state to a file. `jobs pause --all` (or `--from <record>`) pauses them. `jobs resume --from <record>` resumes, on the target, exactly the jobs that were active, matched by id when label, report and owner agree, else by those three; jobs recorded as paused stay paused, and jobs in an error state are listed and left alone. Each run notes the jobs it changes before calling the server, so a rollback or `runs recover --rollback` changes back exactly those.
- **Job states in the export sidecar** (#309, ADR-0059). `jobs resume --from` and `jobs pause --from` also take an export archive or its sidecar. Export **before** pausing the jobs: if they were paused first, every job is recorded as paused, and the resume plan warns you to use the `jobs record` file instead. `export record --jobs` records the configured server's job states for an archive made by hand; use it only against the server that exported the archive. A sidecar without job states is refused with exit 2, never read as "no jobs".
- **`customizations scan --target-vendor <distribution|war> [--out <dir>]`** (#305, ADR-0057). Every site file is classified against the version you upgrade to: `CARRY`, `MERGE`, `OBSOLETE`, `OWN`, `CLASH`, `INSTALLER`, `OVERLAY` or `REMOVED`, with a count per class. `--out` writes `.mine`, `.base` and `.theirs` merge inputs for each `MERGE` file. Nothing is merged or registered.
- **`customizations readiness --target <version>`** (#306, ADR-0061). Before a move to 10.x, which moves to Jakarta EE and Java 17, it lists the site's classes, jars and XML, JSP, tag and TLD files that use renamed `javax.*` classes (`JAKARTA`, or `JAKARTA_SHIPPED` when the target still ships them), Java EE namespaces (`NAMESPACE`), library classes the target's webapp lacks (`NOT_IN_TARGET`, with `--target-vendor`) or a Java above 17 (`BYTECODE`). `--jar` adds a module built outside the webapp. Classes are read from their constant pool; nothing is run, compiled or unpacked, and no class-file library is added. Report only: a file it does not list is not proven ready.
- **`import verify --content [--uri-prefix <folder>]`** (#307, ADR-0060). Also checks that what arrived is identical: every file the archive holds is downloaded and compared by SHA-256, and for other resources the label and description, plus a report unit's data source and input controls. Versions, times, permissions and passwords are left out on purpose, and other descriptor fields are not compared. `--uri-prefix` limits the check to one folder.
- **`--fail-on warn|fail` and `--junit <file>` on `doctor`, `smoke` and `import verify`** (#308, ADR-0058). `--fail-on warn` also exits 2 on a WARN item and never lowers a non-zero exit. `--junit` writes the report as JUnit XML, one testcase per item, so a pipeline that builds a JasperReports Server container image can gate on a test container. The operator guide's *Gating a container image in CI* gives the recipe. jrsctl still does not run inside the image (ADR-0043).

## Known limitations

- **`jobs record`, `pause` and `resume`, and the job states in the sidecar, are tested against a mocked server only.** Whether job ids survive an import, and the state values an 8.2 server reports, are not checked yet. Run `jobs resume --plan` first.
- **`customizations scan --target-vendor` is verified against small fixture webapps and wars only**, not against real 8.2 and 10.0 distributions.
- **`customizations readiness` has been run against the real 10.0.0 webapp, but not against a real 8.2 site.** It reads the names a file uses, not what it does, and does not look for JDK-internal APIs (`jdeps --jdk-internals` does). Build and test the site's code against the target.
- **`import verify --content` has been run against one 10.0.0 PRO server only** (494 files and 113 resources of its samples). It asks for one file at a time, so a whole repository takes a while. Without `--content`, `import verify` still compares by id only.
- **The JUnit file has been checked with the JDK's XML parser only**, not yet in a real CI system's test view.
- **As in 2.7.2:**
  - `repository load` has run against a live server on one machine only (10.0.0 PRO, PostgreSQL, Windows);
  - a jrsctl `export` does not record `sourceDatabase`;
  - `passwords migrate` has never run against a live server;
  - `repository load` supports PostgreSQL and MySQL only;
  - the REST `everything` export below 10.0 may lack calendars;
  - jrsctl does not move a Windows service or systemd unit to a new Tomcat;
  - a buildomatic on a network share (#31), the adapter against live servers other than 10.0.0 PRO (#35), Windows containers not detected, `logs/jrsctl.log` not rotated, and the pager in unusual consoles.
