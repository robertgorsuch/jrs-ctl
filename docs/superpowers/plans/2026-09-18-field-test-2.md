# jrsctl Field Test 2 (v1.6.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the second field test of v1.6.0 into a release the support engineer can apply a vendor hotfix with, run `doctor` without a password on, upgrade with a small `/home` on, and export or import across servers and organisations with, in the order that unblocks the most work first.

**Architecture:** Every finding was checked against `main` at `219d8c9` on 2026-09-18 (`docs/reviews/2026-09-18-field-test-2-review.md`, the "Confirmed" line of each task quotes it). Three findings are already fixed on `main` and unreleased, so Task 0 cuts 1.7.0 first. Then one branch per task, CI-gated on both operating systems, merged into `main` through a PR; tasks 1 to 6 make 1.8.0, tasks 7 to 12 make 1.9.0, task 13 is documentation and lands with whichever release is next, task 14 is hand-offs. Nothing here adds a dependency; the one finding that needs one (tab completion, cursor keys) is handed to the maintainer as the trigger ADR-0023 was waiting for.

**Tech Stack:** Java 21, Maven through `scripts\mvn.cmd` (JDK 21 selector), picocli, JUnit 5 + AssertJ, WireMock (test), google-java-format via Spotless, Error Prone with `-Werror`, JaCoCo floors, GitHub Actions, `gh`.

**Spec:** `docs/spec.md` Draft 1.1 (§0 rules, §5.1 home, §5.4 state store, §8 hotfix, §9 export/import, §10 upgrade, §12 doctor, §13.3 dependencies, §18 exit codes). Inputs: the tester's notes of 2026-09-18, `docs/reviews/2026-09-18-field-test-2-review.md`, `docs/reviews/2026-09-17-vendor-doc-review.md` §4.1, §4.2, ADR-0021, ADR-0023, ADR-0024, ADR-0025, REST API reference 10.1 pp.110 and 117 (`keyAlias`), p.115 (`organization`), p.121 (`mergeOrganization`).

## Global Constraints

- Build only through `scripts\mvn.cmd` (Windows) or `scripts/mvn.sh` (Linux); the default `java` on the dev box is 11.
- `-pl <module>` always with `-am`; with `-Dtest=...` add `-Dsurefire.failIfNoSpecifiedTests=false`; quote every `-D` argument in PowerShell (`"-Dtest=X"`), which otherwise splits on the dot; never `install`.
- `-Werror` + Error Prone: no unused imports or variables, pattern-matching `switch` over sealed types with no `default`.
- `scripts\mvn.cmd spotless:apply` before every commit; `spotless:check` runs in `verify`.
- `core.engine` must not import `core.state`; `jrs` must not depend on `ops` (`Phase0SkeletonTest`).
- All I/O through `Platform`; no `java.io.File`; no `Runtime.exec(String)`; process arguments as lists.
- Secrets in `char[]`; every output stream passes the redaction filter; a password never appears on a command line jrsctl builds except where ADR-0020 already allows it.
- No new third-party dependency without an ADR (spec §13.3). This plan adds none.
- Mutations only inside a `Step`; every `Step.execute` idempotent with a compensation or `irreversible()` with a comment; `IdempotencyCoverageTest` must list every concrete `Step`.
- Read-only operations (`doctor`, `smoke`, `list`) stay plain functions returning a report.
- Tests named `should_<behaviour>_when_<condition>`; one-paragraph Javadoc stating invariants on every new class; vendor rules cite the guide page in the Javadoc.
- Commits: Conventional Commits, one logical change each, `Refs #N` when an issue exists, ending with the attribution lines of the session that executes the task. Write commit messages through a Bash heredoc (`git commit -F - <<'EOF'`), never PowerShell, which adds a BOM (memory `jrsctl-windows-host-traps`).
- After every push: check the `build+unit+acceptance (ubuntu-latest)` job for that commit, not only Windows (memory `jrsctl-check-ubuntu-ci-leg`).
- Coverage floors stay: `core` 0.80, `jrs` 0.78, `ops` 0.80 (`jacoco.line.minimum`).
- Exit codes: 0 ok · 1 usage · 2 precheck · 3 rolled back · 4 rollback incomplete · 5 cancelled · 6 unsupported · 7 signature · 8 recovery required · 9 lock held.
- Every spec change is one entry in `docs/spec-changelog.md` under a dated "Draft 1.1 amendment" heading, the section text in `docs/spec.md`, and the operator guide updated in the same commit.

```java
private static final Pattern WEBAPP_ZIP =
    Pattern.compile("(?i)^jasperserver(-pro)?(-[0-9][^/]*)?\\.zip$");
private static final Pattern INSTALL_ZIP = Pattern.compile("(?i)^js-install(-[0-9][^/]*)?\\.zip$");
private static final Pattern WEBAPP_DIR = Pattern.compile("(?i)^jasperserver(-pro)?/");
private static final String README = "readme.txt";

static boolean looksOfficial(Path zip) {
  return shape(zip).map(s -> s.readme().isPresent() && !s.payloads().isEmpty()).orElse(false);
}

/** What the outer ZIP holds, on basenames; empty when it is not a readable ZIP or holds a manifest. */
static Optional<Shape> shape(Path zip) {
  if (!Files.isRegularFile(zip)) return Optional.empty();
  Optional<String> readme = Optional.empty();
  List<String> payloads = new ArrayList<>();
  try (InputStream in = Files.newInputStream(zip); ZipInputStream z = new ZipInputStream(in)) {
    ZipEntry e;
    while ((e = z.getNextEntry()) != null) {
      String name = e.getName().replace('\\', '/');
      String base = name.substring(name.lastIndexOf('/') + 1);
      if (base.equals(HotfixBundle.MANIFEST)) return Optional.empty();
      if (base.equalsIgnoreCase(README) && readme.isEmpty()) readme = Optional.of(name);
      if (WEBAPP_ZIP.matcher(base).matches() || INSTALL_ZIP.matcher(base).matches()) payloads.add(name);
      else if (!e.isDirectory() && WEBAPP_DIR.matcher(stripPrefix(name)).find()) payloads.add(name);
    }
  } catch (IOException ex) {
    return Optional.empty();
  }
  return Optional.of(new Shape(readme, List.copyOf(payloads)));
}
```

`stripPrefix` removes one leading directory when the entry's first segment is not `jasperserver`/`jasperserver-pro`. The converter (`inner()` and the unpacked-tree branch) resolves entries relative to the readme's directory so a prefixed package maps the same way as a flat one.

/** Rejects traversal, absolute and drive-relative names and control characters; anything else the vendor ships is allowed. */
static Optional<String> entryNameProblem(String name) {
  if (name.isEmpty() || name.startsWith("/") || name.contains("\\") || name.contains(":")) return Optional.of("must be a relative path with forward slashes");
  for (String seg : name.split("/")) if (seg.equals("..") || seg.equals(".")) return Optional.of("must not contain . or .. segments");
  for (char c : name.toCharArray()) if (c < 0x20 || c == 0x7f) return Optional.of("must not contain control characters");

}
