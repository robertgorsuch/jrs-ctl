# jrsctl v1.3.0 Release Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every open, automatable finding on `main` (issues #43, #39, #42, #37, #34, #33, the 42 Dependabot alerts, the untracked `.junie/` directory), record the deferred items as issues, and cut, verify and publish `v1.3.0` through the tag-driven CI release path.

**Architecture:** Work lands on one CI-gated branch `phase/release-1.3.0` (the `ci` workflow builds `phase/**` pushes on both operating systems), one Conventional Commit per logical change, fast-forwarded into `main` only after both CI legs are green. Server-safety fixes go first (one `ServiceSteps`, the Windows vendor export defect, the lingering catalina JVM), then dependencies, then test quality, then documentation, then the release itself. No commit message closes an issue (`Closes #N` fires before CI has verified anything, see session note of 2026-09-14); issues are closed by hand after the tag run is green.

**Tech Stack:** Java 21, Maven through `scripts\mvn.cmd` (JDK 21 selector), JUnit 5 + AssertJ, WireMock 3.13.2 (test), google-java-format via Spotless, Error Prone with `-Werror`, JaCoCo floors, GitHub Actions (`ci.yml`), `gh` CLI.

**Spec:** `docs/spec.md` Draft 1.1 (§0 rules, §4 module map, §5.3 service control, §6.5 backoff, §13.3 approved dependencies, §15 PR checklist, §18 exit codes, §20 release gates). Inputs: `docs/BUILD_STATUS.md`, `docs/reviews/2026-09-13-codebase-assessment.md` §3, GitHub issues #31 to #43, the Dependabot alert list (read on 2026-09-14).

## Global Constraints

- Build only through `scripts\mvn.cmd` (Windows) or `scripts/mvn.sh` (Linux); the default `java` on this machine is 11.
- `-pl <module>` always with `-am`; never `install`.
- `-Werror` + Error Prone: explicit casts, no sealed-subtype constants in the parent, no unused imports.
- `scripts\mvn.cmd spotless:apply` before every commit; `spotless:check` runs in `verify`.
- `core.engine` must not import `core.state`; `jrs` must not depend on `ops` (spec §4, `Phase0SkeletonTest`).
- All I/O through `Platform`; no `java.io.File`; no `Runtime.exec(String)`; arguments as lists.
- Secrets in `char[]`; every output stream passes the redaction filter.
- No new third-party dependency without an ADR (spec §13.3). A version bump of an existing dependency is not a new dependency. Awaitility is **not** approved.
- Mutations only inside a `Step`; every `Step.execute` idempotent with a compensation or `irreversible()` with a comment. `IdempotencyCoverageTest` scans every concrete `Step` in `ops` and `jrs` and must stay complete.
- Tests named `should_<behaviour>_when_<condition>`; one-paragraph Javadoc stating invariants on every public class.
- Commits: Conventional Commits, one logical change each, ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Use `Refs #N`, never `Closes #N`.
- After every push: check the `build+unit+acceptance (ubuntu-latest)` job for that commit, not only the Windows one (memory `jrsctl-check-ubuntu-ci-leg`).
- Coverage floors: `core` 0.80, `jrs` 0.78, `ops` 0.78 today (`jacoco.line.minimum` in each pom); Task 9 raises `ops` to 0.80.
- Exit codes: 0 ok · 1 usage · 2 precheck · 3 rolled back · 4 rollback incomplete · 5 cancelled · 6 unsupported · 7 signature · 8 recovery required · 9 lock held.

```java
package com.jaspersoft.jrsctl.jrs.service;

public interface ServiceRuntime {
  ServiceController controller();
  Duration serviceTimeout();
  Clock clock();
  Sleeper sleeper();
  ServerIdentity refreshIdentity();

  /** Resolves the runtime when the step runs, so a strategy can build steps before a Context exists. */
  @FunctionalInterface
  interface Source {
    ServiceRuntime at(Context ctx);

    static Source fixed(ServiceRuntime rt) {
      Objects.requireNonNull(rt, "rt");
      return ctx -> rt;
    }
  }
}

public final class ServiceSteps {
  public static Step stop(ServiceRuntime rt, String phase, String id);            // = stop(Source.fixed(rt), phase, id)
  public static Step start(ServiceRuntime rt, String phase, String id);
  public static Step waitForServer(ServiceRuntime rt, String phase, String id);
  public static Step stop(ServiceRuntime.Source rt, String phase, String id);
  public static Step start(ServiceRuntime.Source rt, String phase, String id);
  public static Step waitForServer(ServiceRuntime.Source rt, String phase, String id);
  public static CheckResult controllerCheck(ServiceRuntime rt);
  public static StepResult stop(ServiceRuntime rt, BooleanSupplier cancelled);
  public static StepResult start(ServiceRuntime rt, BooleanSupplier cancelled);
}

public final class ContextServiceRuntime implements ServiceRuntime {
  /** Config, platform and adapter are read from the context; clock and sleeper from the polling policy. */
  public static ServiceRuntime.Source source(Polling polling);
}
```

- [ ] **Step 4: Write `ContextServiceRuntime`**

```java
package com.jaspersoft.jrsctl.jrs.service;

/**
 * A {@link ServiceRuntime} the vendor strategy resolves from the run's {@link Context}: the
 * controller comes from {@code Config.toServiceConfig()} through {@code Platform.services}, the
 * stop timeout from the same config, clock and sleeper from the strategy's {@link Polling} policy,
 * and the identity refresh from the registered {@link JrsAdapter}. Invariant: it holds nothing the
 * context does not already hold, so a rebuilt plan (recovery) resolves the same controller.
 */
public final class ContextServiceRuntime implements ServiceRuntime {
  private final Context ctx;
  private final Polling polling;

  private ContextServiceRuntime(Context ctx, Polling polling) {
    this.ctx = Objects.requireNonNull(ctx, "ctx");
    this.polling = Objects.requireNonNull(polling, "polling");
  }

  public static ServiceRuntime.Source source(Polling polling) {
    Objects.requireNonNull(polling, "polling");
    return ctx -> new ContextServiceRuntime(ctx, polling);
  }

  private ServiceConfig serviceConfig() {
    return ctx.service(Config.class).toServiceConfig();   // throws ConfigException, which controllerCheck reports
  }

  @Override public ServiceController controller() { return ctx.platform().services(serviceConfig()); }
  @Override public Duration serviceTimeout() { return serviceConfig().stopTimeout(); }
  @Override public Clock clock() { return polling.clock(); }
  @Override public Sleeper sleeper() { return polling.sleeper(); }
  @Override public ServerIdentity refreshIdentity() { return ctx.service(JrsAdapter.class).refreshIdentity(); }
}
```
