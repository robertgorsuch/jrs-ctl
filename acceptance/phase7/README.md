# Phase 7 acceptance — Distribution

Run: `scripts\mvn.cmd verify -Dphase=7 -Pdist` (the `dist` profile builds the image first; without it the suite is skipped with a hint). Build the image alone with `scripts\build-dist.cmd`.

Criteria (spec §14, Phase 7; ADR-0001..0003, ADR-0008). `Phase7DistributionTest` treats `dist/target/image/<platform>/` and the archive next to it as the unit under test and never touches the JDK that runs Maven: every launcher run has an empty environment except `JRSCTL_HOME`, `PATH` reduced to the Windows system directory (or `/usr/bin:/bin`) and, on Windows, `SystemRoot`/`TEMP` (SQLite extracts its native library to the temp dir). `<platform>` is `windows-x64` here and `linux-x64` on the Linux CI runner.

1. **jlink image + manifest** — `MANIFEST.sha256` exists, every line is `<sha256>  <path>` (format in `dist/README.md`), the set of listed paths equals the set of files on disk (minus the manifest itself), the list is sorted, every hash matches, and `lib/jrsctl.jar`, both launchers, `README.txt` ("Actian Jaspersoft") and `LICENSE-THIRD-PARTY.txt` are present.
2. **No JDK on the host** — `bin\jrsctl.cmd --version` (Linux: `bin/jrsctl --version`) exits 0 and prints `jrsctl <version>` and `Actian Jaspersoft`; `selfcheck` exits 0 with `selfcheck ok` and no `FAIL`; `runs list` exits 0, which proves the SQLite native library loads and `java.sql` is in the runtime.
3. **Portable archive + checksum + SBOM** — `jrsctl-<version>-<platform>.zip|.tar.gz` exists, its `.sha256` sidecar holds `<sha256>  <archive name>` matching the file, `jrsctl-<version>-sbom.json` exists; the archive unpacks (Java `ZipInputStream` on Windows, system `tar` on Linux so exec bits are honoured) into exactly one directory `jrsctl-<version>/` carrying the manifest, and `--version` from the unpacked tree exits 0 with the banner.

Signing (criterion "signing step implemented and executed in CI only", spec §0 rule 11): `scripts/sign-artifacts.cmd|.sh` and the `sign` Maven profile are exercised by the `release` CI job with the `JRSCTL_SIGNING_KEY` secret; locally and in this suite the script only prints `signing skipped: no key (CI only)`. The "clean Windows and Linux VM" smoke is the `package` job's portable-smoke step on the GitHub runners (JAVA_HOME unset, minimal PATH); this suite is the same check on the development machine, where `doctor --home <tmp>` against the image was also run by hand (ADR-0008).
